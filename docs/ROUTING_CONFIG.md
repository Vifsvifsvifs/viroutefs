# Routing configuration

ViRouteFS stores routing configuration locally in `routing_config.json`. The current schema version is 10.

Required built-in profiles are restored during migration:

- `direct` — user-visible `System`;
- `block` — fail-closed target;
- `byedpi` — disabled by default.

The default rule targets `System`, which means the phone's normal mobile-data or Wi-Fi uplink. Network control can start without adding a VPN profile. Explicit app/domain/IP/CIDR rules may select a VPN/proxy, `Block`, **Совместимость TCP/TLS** or `System`.

Older configurations with no default route, or with the old temporary `Block` default, migrate back to `System`. Schema 10 adds IPv6-aware matchers, TCP/UDP and destination-port constraints, plus ordered DNS server lists. Missing new fields keep the previous unrestricted route and legacy single-DNS behavior.

## Secrets

SOCKS5 passwords, VLESS access UUIDs, XHTTP extra JSON and complete advanced profile objects are stored in one AES-256-GCM encrypted envelope in the app’s no-backup directory. Its non-exportable key is held by Android Keystore. Ordinary `routing_config.json` and export omit these secrets. Android application backup is disabled.

## Import/export

Routing JSON export excludes SOCKS5 passwords. Import validates profile references, DNS references, rules, duplicate matchers, IP/CIDR syntax and protocol-specific fields before accepting the configuration.

## Runtime compilation

The model is compiled to pinned sing-box 1.14 alpha JSON:

- invalid/disabled profiles are absent from runtime;
- rules targeting them use Block;
- endpoint and outbound tags are generated by ViRouteFS;
- app rules enable Android process/package lookup;
- explicit rules can add TCP/UDP, exact destination ports and destination-port ranges;
- IPv4 and IPv6 addresses/CIDR networks use the same fail-closed rule model;
- custom DNS rules use the selected detour;
- native libbox validation runs before advanced profiles are saved.
- OpenVPN `.ovpn` import converts common directives and inline certificate/key blocks, reports anything it did not transfer, and still requires native validation.
- WireGuard/wg-quick `.conf` import converts `[Interface]` and multiple `[Peer]` sections to a current sing-box endpoint. Private and pre-shared keys stay encrypted; DNS is selected explicitly in ViRouteFS; shell fields such as `PostUp` are ignored and never executed.

VLESS/XHTTP profiles are compiled separately to a pinned Xray-core
configuration. Xray exposes localhost-only SOCKS endpoints and never owns an
Android TUN. sing-box keeps the single TUN and references only ready endpoints;
missing endpoints compile to `Block`. The generated Xray configuration exists
only in owner-only `noBackupFilesDir` storage while the child process is active.
